# Flaq Open Media Creator

面向創作者、設計師與品牌團隊的開放原始碼
**AI 圖片與影片創作桌面用戶端**。從提示詞靈感、參考素材和無限畫布出發，在同一個工作台中完成生成、預覽、迭代與本機作品整理，讓創作思路更容易變成可交付的內容。

專案改造自 [Flaq SaaS Template](https://github.com/flaqai/flaq-saas-template)，連線 Flaq AI 模型服務，採用 Tauri 2 +
Rust 原生外殼與現代 React 介面。目前安裝後的應用名稱為 **Flaq Creator**。

## AI 創作用戶端功能：從靈感到圖片與影片作品

### AI 圖片生成、影片生成與虛擬試穿

圍繞日常創作提供 8 個入口：可在統一工作台探索想法，也可直接進入專項工具製作電商素材、社交媒體配圖、廣告概念或短影片。

| 創作功能         | 創作者可以做什麼                                         | 頁面路徑              |
| ---------------- | -------------------------------------------------------- | --------------------- |
| AI Media Creator | 在統一工作區創作圖片與影片，檢視生成結果並繼續調整       | `/ai-media-creator`   |
| AI 無限畫布      | 在畫布上組織文字、媒體與生成設定，儲存並繼續本機創作專案 | `/ai-canvas`          |
| 文生圖           | 用提示詞探索視覺風格，製作封面、海報和產品場景圖         | `/text-to-image`      |
| 圖生圖           | 基於參考圖片調整視覺方向，嘗試新的風格與表達             | `/image-to-image`     |
| 虛擬試穿         | 結合服裝與模特兒參考圖，探索穿搭展示與電商創意           | `/virtual-try-on`     |
| 文生影片         | 將文字創意轉化為動態畫面，探索故事與廣告概念             | `/text-to-video`      |
| 圖生影片         | 以靜態圖片作為輸入，製作動態產品展示與視覺片段           | `/image-to-video`     |
| 參考生影片       | 用參考素材引導影片創作，探索連續的視覺表達               | `/reference-to-video` |

頁面路徑省略語言前綴。入口統一維護在 [功能註冊表](./lib/features/catalog.ts)，輸入類型、數量限制和參數以所選模型及
[模型能力設定](./lib/constants/template-models/) 為準。

### 提示詞靈感庫與無限畫布：整理思路、探索創意

- **從範例開始創作**：提示詞素材庫支援複製完整提示詞、圖片／影片預覽，以及縮放和拖動檢視，便於學習構圖與提示詞寫法。範例圖片隨應用提供，範例影片需要連網播放；合集中的模型名稱不代表生成表單已經接入該模型。
- **用畫布組織專案**：在無限畫布上擺放文字、媒體和生成設定，透過平移、縮放與節點操作整理創意，儲存本機專案並在之後繼續編輯。
- **按創作需求選擇模型**：集中調整所選模型支援的參數，結合上下文幫助瞭解輸入要求。首次啟動引導和連線測試幫助完成服務設定，外觀與語言設定調適日常使用習慣。

### 本機素材管理與草稿復原：減少重複整理

- **統一尋找參考素材和作品**：素材目錄聚合已上傳參考素材和生成結果，支援按類型、來源篩選和搜尋，並提供預覽、下載與本機封存狀態。可從
  `/media-library` 或「設定 → 歷史記錄」進入。
- **保留創作進度**：草稿在本機儲存提示詞、參數和輸入素材；工作歷史與上傳素材索引同樣儲存在本機。復原待完成工作時繼續查詢原工作，不會重新提交一次付費生成。
- **自動封存生成作品**：桌面端將完成的圖片與影片按 `YYYY/MM/DD`
  儲存到可設定目錄，方便後續剪輯、設計與交付。封存復原只重試儲存已有結果，不會重新生成。
- **便捷匯出與媒體處理**：支援原生儲存對話方塊、PNG／JPEG／WebP 圖片匯出，以及按需載入的 FFmpeg
  WASM 裁剪，便於把素材帶入後續製作流程。

### 創作者使用流程

1. 在提示詞素材庫尋找靈感，或在畫布中整理文字與參考素材。
2. 選擇創作工具和模型，填寫提示詞、參考素材與可用參數。
3. 提交工作、預覽結果，根據作品效果調整下一次創作。
4. 在素材目錄中尋找作品，將本機封存或匯出的檔案用於後續製作。

真實生成需要連網、有效的 Flaq AI Client Key 和足夠額度。模型在雲端執行；本機草稿、專案和素材索引不提供跨裝置雲端同步。

## 快速開始：執行桌面用戶端並連線 Flaq AI

### 環境要求

- Node.js **22**，與 [.nvmrc](./.nvmrc) 一致。
- pnpm **10.5.2**，與 [package.json](./package.json) 的 `packageManager` 一致。
- 原生開發與封裝需要 Rust 和目標作業系統對應的
  [Tauri 環境依賴](https://v2.tauri.app/start/prerequisites/)。僅建置靜態前端不需要 Rust。
- 真實生成需要 Flaq AI 帳號和 Client Key；預設桌面圖片託管**不要求自行申請 Cloudflare 帳號**。

在本儲存庫根目錄執行：

```bash
pnpm install --frozen-lockfile
pnpm desktop:dev
```

開發版使用獨立應用識別碼 `ai.flaq.creator.dev`，安裝版使用
`ai.flaq.creator`。兩者的設定、WebView 資料和預設作品目錄互相隔離。

### 連線 Flaq AI

1. 登入 [Flaq AI](https://flaq.ai/tw/)，取得 Client Key。
2. 按首次啟動引導操作，或開啟「設定 → 連線」。
3. Base URL 預設使用 `https://api.flaq.ai`；也可以填寫相容且可信的閘道。
4. 填寫 Client Key，測試連線並儲存。
5. 保留內建圖片託管，或主動設定自己的 R2 預設。
6. 選擇工具與模型，填寫提示詞／參考素材後提交；在「設定 → 歷史記錄」管理結果，在「設定 → 一般」修改作品儲存目錄。

> **金鑰儲存方式：**勾選「記住我」後，連線資訊以可讀 JSON 儲存到目前使用者應用設定目錄下的
> `auth.json`。它**不是系統鑰匙圈，也沒有應用層加密**。Unix 下限制為目前使用者存取；不勾選時，工作階段金鑰不會寫入該原生檔案。共享裝置不建議記住金鑰；不要提交金鑰、含敏感資訊的日誌或本機設定。

### 素材上傳流程與本機資料儲存

| 資料／流程       | 目前實作                                                                                                                         |
| ---------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| 桌面內建圖片託管 | 使用 Client Key 向 Flaq 的 `/api/v1/files/presignedUrl` 請求短時簽名連結，再直傳素材；共享 R2 憑證保留在伺服器端，不打進安裝套件 |
| 桌面自訂 R2      | 可選設定帳號 ID、儲存桶、Access Key、Secret Key 與素材公開網域；本機簽名，預設使用 WebView 中的 AES-GCM 儲存，不是系統憑證保險庫 |
| 輸入草稿         | IndexedDB 儲存素材位元組和中繼資料；選中檔案不會立即上傳，提交生成時才上傳                                                       |
| 歷史與素材目錄   | Web Storage 儲存本機工作記錄和已上傳素材索引；目錄記錄不代表素材所有權或雲端刪除權限                                             |
| 生成檔案         | 原生流式儲存到設定目錄，預設位於應用資料目錄；封存失敗不會把已完成生成改成失敗                                                   |

自訂 R2 需要可公開存取素材的網域，而不是直接使用 S3
API 端點。雲端保留時間由 Flaq 服務策略或自己的儲存桶生命週期決定，與本機封存相互獨立。自訂預設的瀏覽器側加密不能防禦被攻陷的 WebView，或能夠讀取應用資料及程式碼的攻擊者；僅使用可信的 API 閘道和上傳目標。

### 可選的 Web 模式

專案保留執行 Next.js 伺服器端的 Web 模式：

```bash
pnpm dev
# Web 生產模式
pnpm build
pnpm start
```

瀏覽器存取 `http://localhost:3000`。如需設定 Web 環境，使用編輯器將 [.env.example](./.env.example) 複製為
`.env.local`，按需填寫：

| 環境變數                                                                      | 用途                               |
| ----------------------------------------------------------------------------- | ---------------------------------- |
| `NEXT_PUBLIC_SITE_URL`、`NEXT_PUBLIC_CONTACT_US_EMAIL`                        | 公開的網站網址與聯絡信箱           |
| `R2_ACCOUNT_ID`、`R2_ACCESS_KEY_ID`、`R2_SECRET_ACCESS_KEY`、`R2_BUCKET_NAME` | Web 上傳簽名介面使用的伺服器端憑證 |

Web 上傳使用
`app/api/upload/presigned-url/route.ts`，並讀取「圖片託管」設定中的公開網域。桌面預設走 Flaq 簽名服務，不需要本機 R2 環境變數，也沒有本機 Next.js
API 服務。不要給任何金鑰添加 `NEXT_PUBLIC_` 前綴，也不要將金鑰放進安裝套件。

## 桌面用戶端技術架構：Tauri 2、Rust 與 Next.js

**Tauri 2 + Rust 承載 Next.js 靜態匯出的介面，安裝套件不內建 Node.js／Next.js 伺服器端。**
桌面端與 Web 端共享 React 頁面、表單、模型契約、翻譯與設計資源。

### 現代技術如何支援創作體驗

- **原生外殼與靜態介面**：Tauri
  2 使用系統 WebView 承載介面，Rust 處理系統視窗、設定和檔案儲存；桌面安裝套件無需執行本機 Node.js 服務。
- **型別與輸入驗證**：TypeScript、共享模型契約和 Zod 驗證統一表單與請求的資料約定，幫助減少參數不符，讓新增模型能力更易維護。
- **非同步工作與按需載入**：集中管理工作輪詢、限制上傳並行，FFmpeg 和自訂 R2 簽名模組按需載入，減少不必要的啟動工作。
- **可靠儲存作品**：Rust 流式下載先寫入暫存檔案，完成後再發佈為目標檔案，減少下載中斷留下不完整成品的風險；生成和封存分別記錄狀態，方便復原。

### 檔案隱私與安全：本機儲存、按需上傳和存取邊界

用戶端透過明確的資料流和檔案存取檢查保護創作資料：

- **草稿先留在本機**：輸入素材位元組和中繼資料儲存在 IndexedDB；選中檔案不會立即上傳，提交生成時才進入上傳流程。
- **上傳憑證按需取得**：預設圖片託管透過 Client Key 取得短時簽名上傳連結，共享 R2 金鑰保留在伺服器端，不隨安裝套件分發。
- **畫布本機檔案按檔案授權**：原生層解析真實路徑，檢查檔案是否為允許的作品目錄中的封存媒體，再為該檔案開放預覽存取。
- **本機設定分開管理**：開發版和安裝版使用獨立應用識別碼，隔離設定與 WebView 資料；Unix 下記住的連線設定檔案限制為目前使用者讀寫。

**隱私邊界：**本機儲存不等於全程離線或檔案加密。提交生成後，相關提示詞和參考素材會傳送到設定的服務，雲端素材保留時間取決於服務或儲存桶策略。記住的 Client
Key 目前以可讀 JSON 儲存，並未接入系統鑰匙圈；詳細儲存方式見上方「素材上傳流程與本機資料儲存」。

無費用模擬生成：先執行 `pnpm build:desktop`，再執行 `node scripts/desktop-preview.mjs`。開啟
`http://127.0.0.1:4173/zh/`，將 Base URL 設定為 `http://127.0.0.1:4173`，Client Key 設定為
`test-only-key`，不要勾選記住。該預覽使用模擬 API，不能驗證真實 Flaq 生成、R2 上傳或原生行為；不要填入真實金鑰。

### 封裝支援範圍

目前儲存庫中的[發佈流程](./.github/workflows/desktop-build.yml)定義如下目標：

| 平台                | 產物                                 |
| ------------------- | ------------------------------------ |
| macOS Apple Silicon | `.dmg` 與包含 `.app` 的 ZIP          |
| macOS Intel         | `.dmg` 與包含 `.app` 的 ZIP          |
| Windows x64         | NSIS `.exe` 安裝套件，不包含 MSI     |
| Linux               | 可從原始碼建置；尚未納入目前發佈矩陣 |

手動觸發只生成候選包；匹配版本的 `desktop-v<version>` 標籤觸發正式發佈流程。發佈匯總產物包括 `SHA256SUMS` 和
`release-manifest.json`。目前流程建置未簽名安裝套件；公開分發仍需平台簽名／公證及原生啟動驗證。「已設定工作流程」不等於「所有平台都已建置和測試通過」。

## 多語言支援與介面在地化 (i18n)

語種註冊表與 README 翻譯包含：
`en`、`ja`、`id`、`it`、`pt`、`es`、`de`、`ru`、`fr`、`zh`、`tw`、`ko`、`th`、`vi`、`ar`。

- 桌面路由始終包含語言前綴，包括 `/en/`；啟動時優先使用已儲存語言，其次系統語言，最後英語。繁體中文系統變體映射到 `tw`。
- Web 英語使用 `/`，其他語言使用前綴；阿拉伯語設定 RTL 文件方向。
- **目前限制：**部分新增設定、素材目錄與提示詞素材庫文案直接使用中英文。 `zh`／`tw`
  共用中文文案，其他語言在這些面板中回復到英文；註冊了 15 個語種不代表每條新介面文案都已翻譯完成。
- 新增語種需同步 [i18n/languages.ts](./i18n/languages.ts)、`messages/`、路由與建置的語種處理、對應 README 和一致性測試。
