# 新增功能模块指南

新增功能优先扩展现有契约，不复制一个完整页面再分别维护。

1. **登记入口**：在 `lib/features/catalog.ts`
   添加稳定 ID、路由、导航翻译键、图标和分组。首页和侧栏自动使用同一份注册表。
2. **声明模型能力**：在 `lib/constants/template-models/`
   定义支持的输入、数量限制、参数和默认值。复用统一生成器或现有图片/视频表单；不要在页面里硬编码模型限制。
3. **添加页面**：在 `app/[locale]` 对应分组增加页面；设置 locale 静态参数所需上下文。完整说明、示例和 FAQ 放入
   `DesktopFeatureInfo`，工作区只展示任务所需内容。
4. **新增服务契约**：服务请求和结果类型放 `network/<module>`。统一经过 `openApiFetchJson` 或 `lib/platform/http`；不得把
   `/api/*` 当作桌面服务端。
5. **复用公共能力**：上传调用 `uploadFiles`，素材读取/下载调用 `lib/platform/media`，图片格式导出调用
   `exportImage`，外链调用 `openExternalUrl`。需要新任务类型时扩展轮询适配层，不在组件内新建定时器。
6. **管理状态**：页面草稿与历史分离；只在真正需要跨页面共享时增加 store。离开视图不得取消后台已提交任务；明确“停止监听”和“取消远端任务”的区别。
7. **本地化**：补齐 15 个 `messages/*.json` 的同名键；使用 `start/end`、`ms/me`、`ps/pe`
   等逻辑方向样式，实测阿拉伯语 RTL。新增图标需显式登记映射。
8. **性能约束**：模型 SDK、FFmpeg、原生插件使用动态导入；大视频不经过 JS 下载缓冲；共享媒体处理串行化；上传并发和轮询周期统一配置。
9. **回归与基线**：增加成功、失败、超时、取消、重试和缺失配置测试。上游模型校验基于已确认提交的 fixture，不要为了让测试通过随意刷新快照；新模型可以添加，但原有模型契约变化需要单独审查。
10. **交付门槛**：运行 `pnpm check`、`pnpm build`、`pnpm build:desktop`
    和 Rust 测试；至少手动覆盖生成、历史恢复、上传失败、格式导出、语言切换与外链。新增原生权限要逐项说明用途，并在目标系统验证。

## 可复现的无费用 UI 测试

运行 `pnpm build:desktop`，然后运行 `node scripts/desktop-preview.mjs`，打开
`http://127.0.0.1:4173/zh/`。在该测试页面中设置 Base URL 为 `http://127.0.0.1:4173`，Client Key 为
`test-only-key`，不要勾选“记住我”。文生图/文生视频会返回项目自带的演示素材，不调用 Flaq，不产生生成费用。这个服务不是生产后端，不能证明真实模型生成质量或 R2 上传可用。

上游基线和实际测试边界见 [Review 报告](REVIEW_REPORT.md)。
