# Flaq Open Media Creator

クリエイター、デザイナー、ブランドチーム向けのオープンソース
**AI 画像・動画制作デスクトップアプリ**。プロンプトのアイデア、参照素材、無限キャンバスを一つのワークスペースにまとめ、生成、プレビュー、調整、作品のローカル整理まで行えます。

[Flaq SaaS Template](https://github.com/flaqai/flaq-saas-template) を基に、Tauri 2 +
Rust のデスクトップシェルとモダンな React UI から Flaq AI のモデルサービスに接続します。インストール後のアプリ名は
**Flaq Creator** です。

## AI デスクトップ機能：アイデアから画像・動画作品へ

### AI 画像生成・動画制作・バーチャル試着

日々の制作に使える 8 つの入口を用意しています。統合ワークスペースでアイデアを試したり、専用ツールで商品ビジュアル、SNS コンテンツ、広告案、短編動画を作成したりできます。

| 制作ツール        | できること                                                       | パス                  |
| ----------------- | ---------------------------------------------------------------- | --------------------- |
| AI Media Creator  | 画像と動画を一つの作業画面で制作し、結果を確認してアイデアを調整 | `/ai-media-creator`   |
| AI 無限キャンバス | テキスト、素材、生成設定をローカルプロジェクトに整理・保存       | `/ai-canvas`          |
| テキストから画像  | プロンプトで表紙、ポスター、商品シーンの表現を探索               | `/text-to-image`      |
| 画像から画像      | 参照画像を基に新しいスタイルや視覚表現を展開                     | `/image-to-image`     |
| バーチャル試着    | 服とモデルの参照画像を組み合わせ、ファッションや商品展示を検討   | `/virtual-try-on`     |
| テキストから動画  | 文章のアイデアを動くシーンや広告案に変換                         | `/text-to-video`      |
| 画像から動画      | 静止画を使って動きのある商品ビジュアルやクリップを制作           | `/image-to-video`     |
| 参照素材から動画  | 参照素材を使って動画生成を誘導                                   | `/reference-to-video` |

パスは言語プレフィックスを省略しています。ツールは[機能レジストリ](./lib/features/catalog.ts)を共有し、入力、制限、パラメーターは選択モデルと[モデル契約](./lib/constants/template-models/)によって異なります。

### プロンプト集と無限キャンバスでアイデアを探索

- **作例から始める**：プロンプト素材ライブラリで全文をコピーし、画像・動画を拡大・移動して確認できます。作例画像は同梱、動画はオンライン再生です。コレクションのモデル名は生成フォームへの対応を保証しません。
- **プロジェクトを視覚的に整理**：キャンバス上にテキスト、素材、生成設定を配置。移動、拡大縮小、ノード操作を使い、ローカル保存して後から編集を再開できます。
- **用途に合うモデルを選ぶ**：状況に応じたヘルプを見ながら対応パラメーターを調整。初回ガイドと接続テストで設定を進め、外観と言語を日常の使い方に合わせられます。

### ローカル素材ライブラリ・下書き復元・作品の書き出し

- **参照素材と完成作品を探す**：アップロード済み素材と生成結果を種類・出所で検索し、プレビュー、ダウンロード、ローカル保存状況を確認できます。`/media-library`
  または「設定 → 履歴」から開きます。
- **制作の進捗を保持**：下書きはプロンプト、パラメーター、入力素材をローカル保存。タスク履歴とアップロード素材索引も端末に残ります。保留タスクの復元は元のタスクを照会し、有料生成を再送信しません。
- **完成作品を自動保存**：画像と動画を指定フォルダーの `YYYY/MM/DD`
  以下に保存し、後の編集や納品に活用できます。保存の復旧では既存結果の保存だけを再試行します。
- **次の制作工程へ**：OS 標準の保存ダイアログ、PNG/JPEG/WebP 書き出し、必要時に読み込む FFmpeg
  WASM のトリミングを利用できます。

### クリエイターの基本的な制作フロー

1. プロンプトの作例を探すか、キャンバスでテキストと参照素材を整理します。
2. ツールとモデルを選び、プロンプト、参照素材、対応パラメーターを設定します。
3. 送信して結果を確認し、次の生成を調整します。
4. ライブラリから作品を探し、保存・書き出したファイルを次の工程で使います。

生成にはネット接続、有効な Flaq AI Client
Key、十分なクレジットが必要です。モデルはクラウドで動作し、ローカルの下書き、プロジェクト、素材索引には端末間のクラウド同期はありません。

## クイックスタート：デスクトップアプリの起動と Flaq AI 接続

### 必要な環境

- [.nvmrc](./.nvmrc) に対応する Node.js **22**。
- [package.json](./package.json) の `packageManager` に対応する pnpm **10.5.2**。
- ネイティブ開発・パッケージ作成には Rust と対象 OS の
  [Tauri 依存関係](https://v2.tauri.app/start/prerequisites/)。フロントエンドのみのビルドには Rust は不要です。
- 実際の生成には Flaq AI アカウントと Client Key。既定のアップロードに独自の Cloudflare アカウントは**不要**です。

リポジトリのルートで実行：

```bash
pnpm install --frozen-lockfile
pnpm desktop:dev
```

開発版のアプリ ID は `ai.flaq.creator.dev`、インストール版は
`ai.flaq.creator`。設定、WebView データ、既定の素材ディレクトリを分離します。

### Flaq AI への接続

1. [Flaq AI](https://flaq.ai/ja/) にログインし、Client Key を取得します。
2. 初回ガイドに従うか、「設定 → 接続」を開きます。
3. 既定の Base URL `https://api.flaq.ai`、または互換性のある信頼できるゲートウェイを指定します。
4. Client Key を入力し、接続をテストして保存します。
5. 内蔵アップロード先を使うか、独自の R2 プリセットを明示的に設定します。
6. ツールとモデルを選び、プロンプト／参照素材を入力して送信。「設定 → 履歴」で結果を管理し、「設定 → 一般」で保存フォルダーを変更できます。

> **認証情報の保存：**「記憶する」を選ぶと、現在のユーザーのアプリ設定ディレクトリに読み取り可能な JSON として
> `auth.json` を保存します。**OS キーチェーンやアプリレベルの暗号化ではありません。**
> Unix の権限は現在のユーザーに限定し、セッション限定の認証情報はこのネイティブファイルに保存しません。共有端末では記憶を避け、キー、秘密を含むログ、ローカル設定をコミットしないでください。

### 素材アップロードとローカルデータ保存

| 対象                           | 現在の実装                                                                                                                                                                                 |
| ------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| デスクトップの内蔵アップロード | Client Key で Flaq の `/api/v1/files/presignedUrl` から短期署名 URL を取得して直接アップロード。共有 R2 認証情報はサーバーに残り、同梱されません。                                         |
| 独自の R2                      | アカウント ID、バケット、アクセスキー、秘密キー、素材公開ドメインを任意設定。署名はローカルで実行し、プリセットは WebView の AES-GCM ストレージに保存。OS の認証情報保管庫ではありません。 |
| 入力の下書き                   | IndexedDB に素材バイト列とメタデータを保存。ファイル選択時にはアップロードせず、生成送信時にアップロードします。                                                                           |
| 履歴と素材一覧                 | ローカル Web Storage にタスクとアップロード素材の索引を保存。一覧への登録は所有権やクラウド削除権限を意味しません。                                                                        |
| 生成ファイル                   | 指定した素材ルートへネイティブのストリーミング保存。既定はアプリデータディレクトリ。保存失敗で生成成功が失敗に変わることはありません。                                                     |

独自 R2 には S3
API エンドポイントだけでなく、公開アクセス可能な素材ドメインが必要です。保持期間は Flaq のサービス方針またはバケットのライフサイクルに従い、ローカル保存とは独立しています。プリセットのブラウザー側暗号化は、侵害された WebView やアプリのプロファイルとコードを読める攻撃者からは保護しません。信頼できる API ゲートウェイとアップロード先を使用してください。

### 任意の Web モード

サーバーを実行する元の Next.js Web モードも利用できます：

```bash
pnpm dev
pnpm build
pnpm start
```

`http://localhost:3000` を開きます。Web 環境を設定する場合は、エディターで [.env.example](./.env.example) を
`.env.local` にコピーし、必要な項目だけ入力します。

| 変数                                                                          | 用途                                             |
| ----------------------------------------------------------------------------- | ------------------------------------------------ |
| `NEXT_PUBLIC_SITE_URL`, `NEXT_PUBLIC_CONTACT_US_EMAIL`                        | 公開サイト URL と連絡先                          |
| `R2_ACCOUNT_ID`, `R2_ACCESS_KEY_ID`, `R2_SECRET_ACCESS_KEY`, `R2_BUCKET_NAME` | Web アップロード署名ルートのサーバー専用認証情報 |

Web アップロードは `app/api/upload/presigned-url/route.ts`
と画像ホスティング設定の公開ドメインを使用します。デスクトップの既定経路は Flaq の署名を使うため、ローカルの R2 環境変数や Next.js
API サーバーは不要です。秘密情報に `NEXT_PUBLIC_` を付けたり、インストーラーに含めたりしないでください。

## デスクトップ技術構成：Tauri 2・Rust・Next.js

**Tauri 2 + Rust が静的エクスポートした Next.js UI を表示します。Node.js／Next.js サーバーは同梱しません。**
デスクトップと Web は React ページ、フォーム、モデル契約、翻訳、デザイン資産を共有します。

### 日々の制作を支えるモダンな技術

- **ネイティブシェルと静的 UI**：Tauri
  2 がシステム WebView を使用し、Rust がウィンドウ、設定、ファイル保存を処理。インストール版にローカル Node.js サーバーは不要です。
- **型と入力検証**：TypeScript、共有モデル契約、Zod によりフォームと API 要求を揃え、パラメーターの不一致を減らしモデル連携を容易にします。
- **非同期タスクと必要時の読み込み**：集中ポーリングとアップロード並列数の制限で処理を調整。FFmpeg と独自 R2 署名は必要時に読み込み、起動時の余分な処理を減らします。
- **信頼性の高い作品保存**：Rust が一時ファイルへストリーミングし、完了後に公開することで、中断時に不完全な作品が残るリスクを軽減。生成と保存の状態を分けて復旧を支援します。

### ファイルのプライバシーと安全性：ローカル保存とアップロード制御

明確なデータフローとファイルアクセス検査で制作素材を保護します：

- **下書きをまずローカルに保存**：IndexedDB に入力素材とメタデータを保持。選択だけではアップロードせず、生成を送信した時点で開始します。
- **短期アップロード権限**：内蔵プロバイダーは Client
  Key で署名 URL を取得。共有 R2 認証情報はサービス側に保持し、アプリには同梱しません。
- **キャンバスのファイル単位のアクセス**：ネイティブコードが実パスを解決し、許可された出力ディレクトリ内の保存済み素材であることを確認してから、そのファイルのプレビューを許可します。
- **ローカル設定の分離**：開発版とインストール版は別 ID と WebView データを使用。Unix の記憶済み接続ファイルは現在のユーザーのみ読み書きできます。

**プライバシーの範囲：**ローカル保存は完全オフライン処理やファイル暗号化を意味しません。生成時は関連プロンプトと参照素材を設定済みサービスに送信し、クラウドでの保持はサービス／バケットの方針に従います。記憶済み Client
Key は OS キーチェーンではなく可読 JSON です。詳細は上記「素材アップロードとローカルデータ保存」を参照してください。

### パッケージの対応状況

登録済みの[リリースワークフロー](./.github/workflows/desktop-build.yml)は以下を定義します：

| 対象                | 成果物                                                   |
| ------------------- | -------------------------------------------------------- |
| macOS Apple Silicon | `.dmg` と `.app` の ZIP                                  |
| macOS Intel         | `.dmg` と `.app` の ZIP                                  |
| Windows x64         | NSIS `.exe` インストーラー。MSI はなし                   |
| Linux               | ソースビルド対象。現在のリリースマトリクスには含みません |

手動実行は候補パッケージを作成し、対応する `desktop-v<version>` タグがリリース公開を開始します。成果物には `SHA256SUMS`
と `release-manifest.json`
を含みます。現在は未署名で、公開配布には OS ごとの署名／公証とネイティブのスモークテストが必要です。ワークフローの定義は全 OS のビルド・テスト成功を証明しません。

## 多言語対応と UI ローカライズ (i18n)

ロケール登録と README 翻訳：`en`, `ja`, `id`, `it`, `pt`, `es`, `de`, `ru`, `fr`, `zh`, `tw`, `ko`, `th`, `vi`, `ar`。

- デスクトップルートは `/en/` を含め常に言語付き。保存言語、システム言語、英語の順で選択し、繁体字中国語の各変種は `tw`
  に対応します。
- Web は英語が `/`、他言語はプレフィックス付き。アラビア語は RTL です。
- **現在の制限：**新しい設定・素材・プロンプトライブラリの一部は中国語と英語を直接記述しています。`zh`/`tw`
  は中国語を共有し、他ロケールは英語にフォールバックします。15 ロケール登録は全 UI 文字列の翻訳完了を意味しません。
- 言語追加には
  [i18n/languages.ts](./i18n/languages.ts)、`messages/`、ルーティング／ビルド処理、README、整合性テストを更新します。
