# Flaq Open Media Creator

**تطبيق سطح مكتب مفتوح المصدر لإنشاء الصور والفيديو بالذكاء الاصطناعي** للمبدعين والمصممين وفرق العلامات التجارية. اجمع
أفكار الأوامر النصية والوسائط المرجعية واللوحة اللامحدودة لإنشاء أعمالك ومعاينتها وتحسينها وتنظيمها محليًا.

التطبيق مشتق من [Flaq SaaS Template](https://github.com/flaqai/flaq-saas-template)، ويتصل بخدمات نماذج Flaq AI عبر غلاف
Tauri 2 + Rust وواجهة React حديثة. اسم التطبيق بعد التثبيت هو **Flaq Creator**.

## منصة نماذج Flaq AI وأدوات الإبداع عبر الإنترنت

تجمع [Flaq AI](https://flaq.ai/ar/) نماذج رائدة لتوليد الصور وتحريرها، وإنشاء الفيديو، والمهام اللغوية للمبدعين
والمطورين والشركات.

- **واجهات API مستقرة بتزامن عالٍ** — ادمج التوليد بالذكاء الاصطناعي في منتجاتك ومسارات الإنتاج عبر واجهة موحدة.
- **أنشئ مباشرة عبر الإنترنت** — جرّب النماذج والأدوات في المتصفح على [Flaq AI](https://flaq.ai/ar/) دون برمجة أو تثبيت
  التطبيق.
- **استكشف وادمج** — قارن النماذج في [سوق النماذج](https://flaq.ai/ar/model-market/) وابدأ باستخدام
  [وثائق API](https://flaq.ai/ar/docs/).

للتواصل التجاري: [contact@flaq.ai](mailto:contact@flaq.ai)

## ميزات تطبيق الذكاء الاصطناعي: من الفكرة إلى الصور والفيديو

### توليد الصور وإنشاء الفيديو وتجربة الملابس الافتراضية

ثمانية مداخل تدعم العمل الإبداعي اليومي. استكشف الأفكار في المساحة الموحدة أو استخدم أدوات متخصصة لصور المنتجات والمحتوى
الاجتماعي ومفاهيم الحملات والمقاطع القصيرة.

| الأداة             | ما يمكن إنشاؤه                                                    | المسار                |
| ------------------ | ----------------------------------------------------------------- | --------------------- |
| AI Media Creator   | إنشاء الصور والفيديو معًا ومراجعة النتائج وتحسين الأفكار          | `/ai-media-creator`   |
| لوحة AI اللامحدودة | تنظيم النصوص والوسائط وإعدادات التوليد في مشروع محلي محفوظ        | `/ai-canvas`          |
| نص إلى صورة        | استكشاف أنماط الأغلفة والملصقات ومشاهد المنتجات من الأوامر النصية | `/text-to-image`      |
| صورة إلى صورة      | تطوير أنماط واتجاهات بصرية جديدة من الصور المرجعية                | `/image-to-image`     |
| تجربة افتراضية     | دمج مراجع الملابس والعارضين لأفكار الأزياء والتجارة               | `/virtual-try-on`     |
| نص إلى فيديو       | تحويل الأفكار المكتوبة إلى مشاهد متحركة ومفاهيم حملات             | `/text-to-video`      |
| صورة إلى فيديو     | إنشاء عروض منتجات متحركة ومقاطع من صور ثابتة                      | `/image-to-video`     |
| مرجع إلى فيديو     | توجيه إنشاء الفيديو بالوسائط المرجعية                             | `/reference-to-video` |

المسارات لا تتضمن بادئة اللغة. تشترك الأدوات في [سجل الميزات](./lib/features/catalog.ts). تعتمد المدخلات والحدود
والمعلمات على النموذج المحدد و[عقود النماذج](./lib/constants/template-models/).

### مكتبة الأوامر النصية واللوحة اللامحدودة لاستكشاف الأفكار

- **ابدأ بالأمثلة**: تصفح المكتبة وانسخ الأوامر كاملة وافحص معاينات الصور والفيديو بالتكبير والتحريك. صور الأمثلة
  مضمّنة، والفيديو يُبث عبر الإنترنت. اسم النموذج في مجموعة لا يضمن توفره في نماذج التوليد.
- **نظّم المشاريع بصريًا**: وزّع النصوص والوسائط والإعدادات على اللوحة، وحرّك العرض وكبّره وتعامل مع العقد. احفظ مشروعًا
  محليًا لاستكماله لاحقًا.
- **اختر النموذج للمهمة**: اضبط المعلمات المدعومة بمساعدة سياقية. يساعد دليل البداية واختبار الاتصال على الإعداد، وتتكيف
  خيارات المظهر واللغة مع استخدامك اليومي.

### مكتبة وسائط محلية واستعادة المسودات وتصدير الأعمال

- **اعثر على المراجع والأعمال**: ابحث في المراجع المرفوعة والنتائج حسب النوع والمصدر، وعاينها ونزّلها وتحقق من الأرشفة
  المحلية. افتح `/media-library` أو الإعدادات ← السجل.
- **احتفظ بالتقدم**: تحفظ المسودات الأوامر والمعلمات والوسائط محليًا، وتبقى سجلات المهام وفهارس المراجع على الجهاز.
  تستعلم الاستعادة عن المهمة الأصلية دون إرسال توليد مدفوع جديد.
- **أرشف النتائج**: تُحفظ الصور والفيديو تحت `YYYY/MM/DD` في مجلد قابل للتغيير للتحرير والتسليم. تعيد استعادة الأرشيف
  محاولة حفظ النتائج الموجودة دون توليد جديد.
- **جهّز المرحلة التالية**: استخدم حوارات الحفظ الأصلية وتصدير PNG/JPEG/WebP والقص عبر FFmpeg WASM المحمّل عند الحاجة.

### سير عمل عملي للمبدعين

1. استكشف أمثلة الأوامر أو نظّم النصوص والمراجع على اللوحة.
2. اختر الأداة والنموذج واضبط الأمر والمراجع والمعلمات المتاحة.
3. أرسل الطلب وراجع النتائج وحسّن التوليد التالي.
4. اعثر على النتائج في المكتبة واستخدم الملفات المؤرشفة أو المصدّرة في بقية الإنتاج.

يتطلب التوليد اتصالًا بالشبكة وClient Key صالحًا من Flaq AI ورصيدًا كافيًا. تعمل النماذج في السحابة؛ لا توفر المسودات
والمشاريع والفهارس المحلية مزامنة سحابية بين الأجهزة.

## البدء: تشغيل التطبيق وربطه بـ Flaq AI

### المتطلبات

- Node.js **22** وفق [.nvmrc](./.nvmrc).
- pnpm **10.5.2** وفق `packageManager` في [package.json](./package.json).
- Rust و[متطلبات Tauri](https://v2.tauri.app/start/prerequisites/) لنظام التشغيل المستهدف للتطوير والحزم الأصلية. بناء
  الواجهة فقط لا يحتاج Rust.
- حساب Flaq AI وClient Key للتوليد الحقيقي. الرفع الافتراضي **لا** يحتاج حساب Cloudflare خاصًا بك.

من جذر المستودع:

```bash
pnpm install --frozen-lockfile
pnpm desktop:dev
```

يستخدم التطوير `ai.flaq.creator.dev` والتطبيق المثبت `ai.flaq.creator`. الإعدادات وبيانات WebView ومجلدات الوسائط
الافتراضية منفصلة.

### الاتصال بـ Flaq AI

1. سجّل الدخول إلى [Flaq AI](https://flaq.ai/ar/) واحصل على Client Key.
2. اتبع دليل البداية أو افتح الإعدادات ← الاتصال.
3. استخدم Base URL الافتراضي `https://api.flaq.ai` أو بوابة متوافقة موثوقة.
4. أدخل المفتاح واختبر الاتصال ثم احفظ.
5. احتفظ بمزود الرفع المدمج أو اضبط إعداد R2 الخاص بك صراحةً.
6. اختر الأداة والنموذج وأدخل الأمر/المراجع وأرسل. أدر النتائج من الإعدادات ← السجل، وغيّر مجلد الأرشيف من الإعدادات ←
   عام.

> **تخزين بيانات الاعتماد:** يحفظ خيار «تذكرني» JSON قابلًا للقراءة في `auth.json` داخل مجلد إعدادات المستخدم الحالي.
> هذا **ليس مخزن مفاتيح نظام التشغيل ولا تشفيرًا على مستوى التطبيق**. تقتصر صلاحيات Unix على المستخدم الحالي؛ بيانات
> الجلسة فقط لا تُكتب في هذا الملف الأصلي. تجنب حفظ المفاتيح على الأجهزة المشتركة، ولا تضع المفاتيح أو السجلات المحتوية
> على أسرار أو الإعدادات المحلية في commits.

### رفع الوسائط وتخزين البيانات محليًا

| المجال          | التنفيذ الحالي                                                                                                                                           |
| --------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------- |
| الرفع المدمج    | يطلب Client Key روابط موقعة قصيرة العمر من `/api/v1/files/presignedUrl` ثم تُرفع الوسائط مباشرة. تبقى بيانات R2 المشتركة في الخادم ولا تُضمّن في الحزمة. |
| R2 مخصص         | معرّف الحساب والحاوية ومفتاح الوصول والسر والنطاق العام اختيارية. التوقيع محلي والإعدادات محفوظة بـ AES-GCM داخل WebView، لا في خزنة النظام.             |
| المسودات        | يخزن IndexedDB البايتات والبيانات الوصفية. اختيار الملف لا يرفعه؛ يبدأ الرفع عند الإرسال.                                                                |
| السجل والفهرس   | يفهرس Web Storage المحلي المهام والمراجع المرفوعة. الإدراج لا يمنح ملكية أو صلاحية حذف سحابي.                                                            |
| الملفات الناتجة | حفظ أصلي متدفق إلى جذر الوسائط المحدد، وافتراضيًا إلى مجلد بيانات التطبيق. فشل الأرشفة لا يلغي نجاح التوليد.                                             |

يحتاج R2 المخصص نطاق وسائط متاحًا للعامة، لا مجرد نقطة اتصال S3. تحدد سياسة Flaq أو دورة حياة الحاوية مدة الاحتفاظ؛
الأرشفة المحلية مستقلة. تشفير الإعدادات داخل المتصفح لا يحمي من WebView مخترق أو مهاجم يقرأ ملف تعريف التطبيق وكوده.
استخدم بوابات ووجهات رفع موثوقة.

### وضع Web الاختياري

يبقى وضع Next.js الأصلي الذي يشغّل خادمًا متاحًا:

```bash
pnpm dev
pnpm build
pnpm start
```

افتح `http://localhost:3000`. عند إعداد بيئة Web، انسخ [.env.example](./.env.example) إلى `.env.local` بالمحرر وأدخل
القيم اللازمة فقط.

| المتغيرات                                                                     | الاستخدام                          |
| ----------------------------------------------------------------------------- | ---------------------------------- |
| `NEXT_PUBLIC_SITE_URL`, `NEXT_PUBLIC_CONTACT_US_EMAIL`                        | عنوان الموقع العام وبيانات الاتصال |
| `R2_ACCOUNT_ID`, `R2_ACCESS_KEY_ID`, `R2_SECRET_ACCESS_KEY`, `R2_BUCKET_NAME` | بيانات خادم فقط لتوقيع رفع Web     |

يستخدم Web المسار `app/api/upload/presigned-url/route.ts` والنطاق العام المحدد في استضافة الصور. يستخدم سطح المكتب
توقيعات Flaq، دون متغيرات R2 محلية أو خادم Next.js API محلي. لا تسبق الأسرار بـ `NEXT_PUBLIC_` ولا تضعها في المثبتات.

## بنية تطبيق سطح المكتب: Tauri 2 وRust وNext.js

**يستضيف Tauri 2 + Rust واجهة Next.js مصدّرة ثابتًا، دون خادم Node.js/Next.js مضمّن.** يشترك سطح المكتب وWeb في صفحات
React والنماذج وعقود النماذج والترجمات وموارد التصميم.

### تقنيات حديثة للعمل الإبداعي اليومي

- **غلاف أصلي وواجهة ثابتة**: يستخدم Tauri 2 عارض WebView للنظام، ويتولى Rust النوافذ والإعدادات والملفات. لا يلزم خادم
  Node.js محلي.
- **الأنواع والتحقق من المدخلات**: يطابق TypeScript والعقود المشتركة وZod النماذج مع طلبات API، لتقليل اختلاف المعلمات
  وتسهيل التكامل.
- **مهام غير متزامنة ووحدات عند الطلب**: ينسق الاستعلام المركزي وحدّ تزامن الرفع العمل. يُحمّل FFmpeg وتوقيع R2 المخصص
  عند الحاجة، لتقليل العمل غير الضروري عند التشغيل.
- **حفظ موثوق**: ينزّل Rust إلى ملفات مؤقتة ثم ينشر المكتملة، لتقليل الملفات الجزئية بعد الانقطاع. تساعد حالتا التوليد
  والأرشفة المنفصلتان على الاستعادة.

### خصوصية الملفات وأمانها: تخزين محلي ورفع مضبوط

تحمي تدفقات البيانات الواضحة وفحوص الوصول موادك الإبداعية:

- **المسودات محلية أولًا**: يحتفظ IndexedDB بالوسائط وبياناتها. الاختيار وحده لا يرفع الملف؛ يبدأ الرفع عند إرسال
  التوليد.
- **تفويض مؤقت**: يحصل المزود المدمج على روابط موقعة باستخدام Client Key. تبقى بيانات R2 المشتركة لدى الخدمة، خارج
  التطبيق.
- **وصول اللوحة لكل ملف**: يحل الكود الأصلي المسارات الحقيقية ويتحقق من أن الملف وسيط مؤرشف داخل مجلد إخراج مسموح قبل
  منح المعاينة لذلك الملف.
- **إعدادات منفصلة**: للتطوير والتطبيق المثبت معرّفات وبيانات WebView مختلفة. في Unix يقرأ ويكتب ملفات الاتصال المحفوظة
  المستخدم الحالي فقط.

**حدود الخصوصية:** التخزين المحلي لا يعني معالجة كاملة دون إنترنت أو تشفير الملفات. تُرسل الأوامر والمراجع المرتبطة إلى
الخدمات المضبوطة، وتحدد سياسات الخدمة أو الحاوية الاحتفاظ البعيد. تُحفظ Client Keys المتذكَّرة بصيغة JSON مقروءة، لا في
مخزن مفاتيح النظام. راجع «رفع الوسائط وتخزين البيانات محليًا» أعلاه.

مسارات المصدر ولا تُحذف. يتولى HTTP الأصلي API والرفع والتنزيل دون قيود CORS للمتصفح. يُحمّل توقيع AWS لـ R2 المخصص
وFFmpeg المحلي عند الحاجة. الرفع محدود التزامن، ومعالجة الوسائط المشتركة متسلسلة، والاستعلام مركزي.

للوحدات الجديدة وسّع السجل والعقود، وضع منطق API في `network/` وأعد استخدام `lib/platform/` وأضف الترجمات واختبارات
التراجع. راجع:

- [البنية وحدود التخزين](./docs/DESKTOP_ARCHITECTURE.md)
- [إضافة الوحدات وضمان الجودة محليًا](./docs/ADDING_MODULES.md)

- [جرد المنتج](./docs/PRODUCT_INVENTORY.md) و[تقرير المراجعة](./docs/REVIEW_REPORT.md): سجلان لحالة زمنية، لا ضمان
  للتحقق من الإصدار الحالي.

## بناء تطبيق سطح المكتب واختباره وتغليفه

| الأمر                                             | الغرض                                                       |
| ------------------------------------------------- | ----------------------------------------------------------- |
| `pnpm desktop:dev`                                | تجهيز الوسائط وتشغيل واجهة التطوير والتطبيق الأصلي          |
| `pnpm build:desktop`                              | واجهة ثابتة إلى `out/` لكل اللغات المسجلة                   |
| `pnpm desktop:build`                              | بناء الواجهة والحزم الأصلية للنظام الحالي                   |
| `pnpm check`                                      | TypeScript + اختبارات تراجع Node + ESLint                   |
| `pnpm test:ui-layout`                             | اختبارات تخطيط Playwright؛ تتطلب Google Chrome والمنفذ 3000 |
| `cargo test --manifest-path src-tauri/Cargo.toml` | اختبارات Rust أصلية؛ تتطلب تبعيات بناء المنصة المستهدفة     |
| `pnpm prompts:sync`                               | صيانة: تحديث لقطة الأوامر والموارد المختارة من الشبكة       |

للمحاكاة المحلية شغّل `pnpm build:desktop` ثم `node scripts/desktop-preview.mjs`. افتح `http://127.0.0.1:4173/zh/` واضبط
Base URL على `http://127.0.0.1:4173` واستخدم `test-only-key` دون تذكره. لا تتحقق API المحاكاة من توليد Flaq الحقيقي أو
رفع R2 أو السلوك الأصلي. لا تستخدم مفاتيح حقيقية.

### حالة الحزم

يحدد [مسار الإصدار](./.github/workflows/desktop-build.yml) الأهداف التالية:

| الهدف               | المخرجات                                           |
| ------------------- | -------------------------------------------------- |
| macOS Apple Silicon | `.dmg` و`.app` مضغوطة في ZIP                       |
| macOS Intel         | `.dmg` و`.app` مضغوطة في ZIP                       |
| Windows x64         | مثبت NSIS `.exe`؛ دون MSI                          |
| Linux               | بناء من المصدر؛ غير مدرج في مصفوفة الإصدار الحالية |

التشغيل اليدوي ينتج حزمًا مرشحة؛ وسوم `desktop-v<version>` المطابقة تطلق النشر. تتضمن المخرجات `SHA256SUMS`
و`release-manifest.json`. الحزم الحالية غير موقعة؛ التوزيع العام يحتاج توقيعًا/توثيقًا خاصًا بالمنصة وفحص تشغيل أصلي.
وجود مسار إصدار لا يثبت نجاح البناء والاختبار لكل المنصات.

## اللغات وتوطين الواجهة (i18n)

يشمل السجل وترجمات README: `en`, `ja`, `id`, `it`, `pt`, `es`, `de`, `ru`, `fr`, `zh`, `tw`, `ko`, `th`, `vi`, `ar`.

- تتضمن مسارات سطح المكتب اللغة دائمًا، حتى `/en/`. أولوية البدء: اللغة المحفوظة ثم النظام ثم الإنجليزية. تُربط متغيرات
  الصينية التقليدية بـ `tw`.
- يستخدم Web المسار `/` للإنجليزية وبادئات لغيرها. اتجاه العربية RTL.
- **قيد حالي:** بعض النصوص الجديدة في الإعدادات ومكتبتي الوسائط والأوامر مكتوبة مباشرة بالصينية والإنجليزية. تتشارك
  `zh`/`tw` الصينية وتعود اللغات الأخرى للإنجليزية في هذه اللوحات. تسجيل 15 لغة لا يعني ترجمة كل نص جديد.
- أضف اللغات عبر [i18n/languages.ts](./i18n/languages.ts) و`messages/` ومعالجة التوجيه/البناء وملفات README واختبارات
  التطابق.
