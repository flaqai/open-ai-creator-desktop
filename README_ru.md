# Flaq Open Media Creator

**Настольное приложение с открытым исходным кодом для создания изображений и видео с ИИ**, предназначенное для авторов,
дизайнеров и команд брендов. Объедините идеи промптов, референсы и бесконечный холст, чтобы генерировать, просматривать,
улучшать и локально упорядочивать работы.

Приложение адаптировано из [Flaq SaaS Template](https://github.com/flaqai/flaq-saas-template) и подключается к моделям
Flaq AI через оболочку Tauri 2 + Rust и современный интерфейс React. После установки оно называется **Flaq Creator**.

## Возможности ИИ-приложения: от идеи к изображениям и видео

### Генерация изображений, видео и виртуальная примерка

Восемь разделов поддерживают повседневную работу. Исследуйте идеи в общем пространстве или выберите отдельный инструмент
для визуализации товаров, соцсетей, рекламных концепций и коротких видео.

| Инструмент                | Творческие возможности                                                          | Маршрут               |
| ------------------------- | ------------------------------------------------------------------------------- | --------------------- |
| AI Media Creator          | Создавайте изображения и видео вместе, оценивайте результаты и уточняйте идеи   | `/ai-media-creator`   |
| Бесконечный ИИ-холст      | Организуйте тексты, медиа и настройки генерации в сохраняемом локальном проекте | `/ai-canvas`          |
| Текст в изображение       | Исследуйте стили обложек, плакатов и товарных сцен по промптам                  | `/text-to-image`      |
| Изображение в изображение | Развивайте новые стили и визуальные направления по референсам                   | `/image-to-image`     |
| Виртуальная примерка      | Совмещайте референсы одежды и моделей для моды и торговли                       | `/virtual-try-on`     |
| Текст в видео             | Превращайте письменные идеи в движущиеся сцены и рекламные концепции            | `/text-to-video`      |
| Изображение в видео       | Создавайте анимированные товарные материалы и клипы из статичных изображений    | `/image-to-video`     |
| Референсы в видео         | Направляйте создание видео с помощью референсных материалов                     | `/reference-to-video` |

Маршруты указаны без языкового префикса. Инструменты используют общий [реестр функций](./lib/features/catalog.ts).
Входы, ограничения и параметры зависят от модели и [контрактов моделей](./lib/constants/template-models/).

### Библиотека промптов и бесконечный холст для поиска идей

- **Начните с примеров**: изучайте библиотеку, копируйте полные промпты, увеличивайте и перемещайте предпросмотр
  изображений/видео. Примеры изображений включены в приложение, видео воспроизводятся онлайн. Название модели в подборке
  не гарантирует её наличие в формах генерации.
- **Организуйте проекты визуально**: размещайте тексты, медиа и настройки на холсте, перемещайтесь, масштабируйте и
  работайте с узлами. Сохраняйте локальные проекты и продолжайте позже.
- **Выбирайте модель под задачу**: меняйте поддерживаемые параметры с контекстной помощью. Начальный мастер и проверка
  соединения упрощают настройку; внешний вид и язык адаптируют рабочее пространство.

### Локальная медиатека, восстановление черновиков и экспорт

- **Находите референсы и работы**: ищите загруженные материалы и результаты по типу и происхождению, просматривайте,
  скачивайте и проверяйте локальный архив. Откройте `/media-library` или Настройки → История.
- **Сохраняйте прогресс**: промпты, параметры и медиа черновиков остаются локально, как история задач и индексы
  референсов. Восстановление незавершённой задачи проверяет исходную, не запускает новую платную генерацию.
- **Архивируйте результаты**: изображения и видео сохраняются в `YYYY/MM/DD` внутри выбранной папки для дальнейшего
  монтажа и передачи. Восстановление архива повторяет сохранение готовых результатов без новой генерации.
- **Подготовьте следующий этап**: используйте системные диалоги сохранения, экспорт PNG/JPEG/WebP и обрезку через FFmpeg
  WASM, загружаемый по необходимости.

### Практический процесс для авторов

1. Изучите примеры промптов или организуйте тексты и референсы на холсте.
2. Выберите инструмент и модель, задайте промпт, референсы и доступные параметры.
3. Отправьте запрос, оцените результат и улучшите следующую генерацию.
4. Найдите результат в медиатеке и используйте архивированные или экспортированные файлы дальше.

Нужны интернет, действительный Flaq AI Client Key и достаточный баланс. Модели работают в облаке; локальные черновики,
проекты и индексы не синхронизируются между устройствами.

## Начало работы: запуск приложения и подключение Flaq AI

### Требования

- Node.js **22**, как в [.nvmrc](./.nvmrc).
- pnpm **10.5.2**, согласно `packageManager` в [package.json](./package.json).
- Rust и [зависимости Tauri](https://v2.tauri.app/start/prerequisites/) целевой ОС для нативной разработки и упаковки.
  Сборка только интерфейса не требует Rust.
- Аккаунт Flaq AI и Client Key для реальной генерации. Стандартная загрузка **не** требует собственного аккаунта
  Cloudflare.

В корне репозитория:

```bash
pnpm install --frozen-lockfile
pnpm desktop:dev
```

Разработка использует `ai.flaq.creator.dev`, установленное приложение — `ai.flaq.creator`. Их настройки, данные WebView
и стандартные папки медиа разделены.

### Подключение Flaq AI

1. Войдите в [Flaq AI](https://flaq.ai/ru/) и получите Client Key.
2. Следуйте начальному мастеру или откройте Настройки → Подключение.
3. Используйте Base URL `https://api.flaq.ai` либо совместимый доверенный шлюз.
4. Введите ключ, проверьте соединение и сохраните.
5. Оставьте встроенного провайдера загрузки или явно настройте собственный профиль R2.
6. Выберите инструмент и модель, введите промпт/референсы и отправьте. Результаты — в Настройки → История; папка архива
   — в Настройки → Общие.

> **Учётные данные:** «Запомнить меня» сохраняет читаемый JSON в `auth.json` в каталоге настроек текущего пользователя.
> Это **не системное хранилище ключей и не шифрование приложения**. В Unix доступ ограничен текущим пользователем;
> сессионные данные в этот нативный файл не записываются. Не сохраняйте ключи на общих устройствах и не добавляйте в
> коммиты ключи, логи с секретами или локальные настройки.

### Загрузка медиа и локальное хранение

| Область             | Текущая реализация                                                                                                                                                             |
| ------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Встроенная загрузка | Client Key запрашивает краткосрочные подписанные URL у `/api/v1/files/presignedUrl`, затем медиа загружается напрямую. Общие ключи R2 остаются на сервере и не входят в пакет. |
| Собственный R2      | Необязательные ID аккаунта, bucket, ключ доступа, секрет и публичный домен. Подпись локальная; профили AES-GCM в WebView, не в системном хранилище.                            |
| Черновики           | IndexedDB хранит байты и метаданные. Выбор файла не загружает его; загрузка начинается при отправке.                                                                           |
| История и каталог   | Локальный Web Storage индексирует задачи и загруженные референсы. Запись не даёт прав собственности или удаления в облаке.                                                     |
| Готовые файлы       | Нативное потоковое сохранение в выбранную папку, по умолчанию — данные приложения. Ошибка архива не отменяет успешную генерацию.                                               |

Собственному R2 нужен публично доступный домен медиа, не только S3 endpoint. Срок хранения определяется политикой Flaq
или жизненным циклом bucket; локальный архив независим. Шифрование профилей в браузере не защищает от взломанного
WebView или доступа атакующего к профилю и коду приложения. Используйте доверенные шлюзы и назначения загрузки.

### Необязательный Web-режим

Сохранён исходный режим Next.js с сервером:

```bash
pnpm dev
pnpm build
pnpm start
```

Откройте `http://localhost:3000`. Для настройки Web скопируйте [.env.example](./.env.example) в `.env.local` редактором
и заполните только нужные поля.

| Переменные                                                                    | Назначение                                          |
| ----------------------------------------------------------------------------- | --------------------------------------------------- |
| `NEXT_PUBLIC_SITE_URL`, `NEXT_PUBLIC_CONTACT_US_EMAIL`                        | Публичный URL сайта и контакты                      |
| `R2_ACCOUNT_ID`, `R2_ACCESS_KEY_ID`, `R2_SECRET_ACCESS_KEY`, `R2_BUCKET_NAME` | Только серверные данные для подписания Web-загрузок |

Web использует `app/api/upload/presigned-url/route.ts` и публичный домен из настроек хостинга изображений. Desktop по
умолчанию получает подписи Flaq, не требует локальных переменных R2 или сервера Next.js API. Не добавляйте секретам
префикс `NEXT_PUBLIC_` и не включайте их в установщики.

## Архитектура приложения: Tauri 2, Rust и Next.js

**Tauri 2 + Rust размещает статически экспортированный интерфейс Next.js без встроенного сервера Node.js/Next.js.**
Desktop и Web используют общие React-страницы, формы, контракты, переводы и дизайн-ресурсы.

### Современные технологии для творчества

- **Нативная оболочка и статический интерфейс**: Tauri 2 использует системный WebView, Rust управляет окнами,
  настройками и файлами. Локальный сервер Node.js не нужен.
- **Типы и проверка входных данных**: TypeScript, общие контракты и Zod согласуют формы и API, сокращают ошибки
  параметров и упрощают интеграцию моделей.
- **Асинхронные задачи и загрузка по необходимости**: централизованный опрос и ограничение параллельных загрузок
  координируют работу. FFmpeg и подпись собственного R2 загружаются только при необходимости, снижая работу при старте.
- **Надёжное сохранение**: Rust пишет поток в временные файлы и публикует завершённые, уменьшая риск частичных
  результатов после обрыва. Раздельные состояния генерации и архива поддерживают восстановление.

### Конфиденциальность файлов: локальные данные и контролируемая загрузка

Явные потоки данных и проверки доступа защищают материалы:

- **Сначала локальные черновики**: IndexedDB хранит медиа и метаданные. Выбор не отправляет файл; загрузка начинается
  при отправке генерации.
- **Краткосрочное разрешение**: встроенный провайдер получает подписанные URL через Client Key. Общие ключи R2 остаются
  у сервиса, не в приложении.
- **Доступ холста к отдельным файлам**: нативный код разрешает реальные пути и проверяет, что файл — архивированное
  медиа в разрешённой папке, прежде чем открыть предпросмотр.
- **Раздельные настройки**: разработка и установленная версия имеют разные ID и данные WebView. В Unix читать и менять
  сохранённые соединения может только текущий пользователь.

**Границы конфиденциальности:** локальное хранение не означает полностью автономную обработку или шифрование файлов.
Соответствующие промпты и референсы отправляются настроенным сервисам; удалённое хранение определяется их политиками или
bucket. Запомненные Client Key — читаемый JSON, а не системное хранилище ключей. Подробности выше, в разделе «Загрузка
медиа и локальное хранение».

ограничений CORS браузера. Подпись AWS для собственного R2 и локальный FFmpeg загружаются по необходимости.
Параллельность загрузок ограничена, общая обработка медиа последовательна, опрос централизован.

Новые модули расширяют реестр и контракты; API-логика остаётся в `network/`, повторно используется `lib/platform/`,
добавляются переводы и регрессионные тесты. См.:

Для локальной симуляции выполните `pnpm build:desktop`, затем `node scripts/desktop-preview.mjs`. Откройте
`http://127.0.0.1:4173/zh/`, укажите Base URL `http://127.0.0.1:4173` и `test-only-key` без запоминания. Симуляция API
не проверяет реальную генерацию Flaq, R2 или нативное поведение. Не используйте настоящие ключи.

### Состояние пакетов

[Процесс выпуска](./.github/workflows/desktop-build.yml) определяет:

| Платформа           | Артефакты                                         |
| ------------------- | ------------------------------------------------- |
| macOS Apple Silicon | `.dmg` и ZIP с `.app`                             |
| macOS Intel         | `.dmg` и ZIP с `.app`                             |
| Windows x64         | Установщик NSIS `.exe`; без MSI                   |
| Linux               | Сборка из исходников; вне текущей матрицы выпуска |

Ручные запуски создают кандидаты; подходящие теги `desktop-v<version>` запускают публикацию. В комплект входят
`SHA256SUMS` и `release-manifest.json`. Текущие пакеты не подписаны; публичному распространению нужны
подпись/нотаризация для платформы и нативная проверка запуска. Наличие процесса не доказывает успешную сборку и
тестирование всех платформ.

## Языки и локализация интерфейса (i18n)

Реестр и README охватывают: `en`, `ja`, `id`, `it`, `pt`, `es`, `de`, `ru`, `fr`, `zh`, `tw`, `ko`, `th`, `vi`, `ar`.

- Desktop-маршруты всегда содержат локаль, включая `/en/`. Приоритет: сохранённый язык, системный, английский. Варианты
  традиционного китайского соответствуют `tw`.
- Web использует `/` для английского и префиксы для остальных. Арабский — RTL.
- **Текущее ограничение:** часть новых текстов настроек и библиотек медиа/промптов записана напрямую на китайском и
  английском. `zh`/`tw` используют общий китайский текст, остальные — английский в этих панелях. 15 локалей не означают
  перевод каждой новой строки.
- Добавляйте языки через [i18n/languages.ts](./i18n/languages.ts), `messages/`, маршрутизацию/сборку, README и тесты
  соответствия.
