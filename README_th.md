# Flaq Open Media Creator

**แอปเดสก์ท็อปโอเพนซอร์สสำหรับสร้างภาพและวิดีโอด้วย AI** สำหรับครีเอเตอร์ นักออกแบบ และทีมแบรนด์
รวมแรงบันดาลใจจากพรอมป์ต์ สื่ออ้างอิง และแคนวาสไม่จำกัดไว้ในพื้นที่เดียว เพื่อสร้าง ดูตัวอย่าง ปรับปรุง
และจัดเก็บผลงานในเครื่อง

พัฒนาต่อยอดจาก [Flaq SaaS Template](https://github.com/flaqai/flaq-saas-template) เชื่อมต่อโมเดล Flaq AI ผ่าน Tauri 2 +
Rust และหน้าจอ React สมัยใหม่ ชื่อแอปหลังติดตั้งคือ **Flaq Creator**

## ฟีเจอร์ AI บนเดสก์ท็อป: จากไอเดียสู่ภาพและวิดีโอ

### สร้างภาพ วิดีโอ และลองเสื้อผ้าเสมือนจริง

มี 8 ทางเข้าสำหรับงานสร้างสรรค์ประจำวัน สำรวจไอเดียในพื้นที่รวม หรือใช้เครื่องมือเฉพาะเพื่อสร้างภาพสินค้า เนื้อหาโซเชียล
แนวคิดโฆษณา และวิดีโอสั้น

| เครื่องมือ            | สิ่งที่สร้างได้                                            | เส้นทาง               |
| --------------------- | ---------------------------------------------------------- | --------------------- |
| AI Media Creator      | สร้างภาพและวิดีโอในที่เดียว ตรวจผลลัพธ์และปรับไอเดีย       | `/ai-media-creator`   |
| แคนวาส AI ไม่จำกัด    | จัดข้อความ สื่อ และค่าการสร้างในโปรเจกต์ที่บันทึกในเครื่อง | `/ai-canvas`          |
| ข้อความเป็นภาพ        | สำรวจสไตล์หน้าปก โปสเตอร์ และฉากสินค้าจากพรอมป์ต์          | `/text-to-image`      |
| ภาพเป็นภาพ            | พัฒนาสไตล์และทิศทางภาพใหม่จากภาพอ้างอิง                    | `/image-to-image`     |
| ลองเสื้อผ้าเสมือนจริง | รวมภาพเสื้อผ้าและนางแบบ/นายแบบสำหรับแนวคิดแฟชั่นและการค้า  | `/virtual-try-on`     |
| ข้อความเป็นวิดีโอ     | เปลี่ยนไอเดียที่เขียนเป็นฉากเคลื่อนไหวและแนวคิดแคมเปญ      | `/text-to-video`      |
| ภาพเป็นวิดีโอ         | สร้างภาพสินค้าเคลื่อนไหวและคลิปจากภาพนิ่ง                  | `/image-to-video`     |
| สื่ออ้างอิงเป็นวิดีโอ | ใช้สื่ออ้างอิงกำหนดแนวทางการสร้างวิดีโอ                    | `/reference-to-video` |

เส้นทางไม่รวมคำนำหน้าภาษา เครื่องมือใช้ [ทะเบียนฟีเจอร์](./lib/features/catalog.ts) ร่วมกัน อินพุต ขีดจำกัด
และพารามิเตอร์ขึ้นอยู่กับโมเดลและ [ข้อกำหนดโมเดล](./lib/constants/template-models/)

### คลังพรอมป์ต์และแคนวาสไม่จำกัดสำหรับสำรวจไอเดีย

- **เริ่มจากตัวอย่าง**: เปิดคลัง คัดลอกพรอมป์ต์เต็ม และซูมหรือเลื่อนดูภาพ/วิดีโอตัวอย่าง ภาพรวมอยู่ในแอป
  ส่วนวิดีโอเล่นออนไลน์ ชื่อโมเดลในคอลเลกชันไม่ได้รับประกันว่ามีในแบบฟอร์มสร้าง
- **จัดโปรเจกต์อย่างเป็นภาพ**: วางข้อความ สื่อ และค่าการสร้างบนแคนวาส เลื่อน ซูม และจัดการโหนด
  แล้วบันทึกโปรเจกต์ในเครื่องเพื่อทำต่อภายหลัง
- **เลือกโมเดลให้เหมาะกับงาน**: ปรับพารามิเตอร์ที่รองรับพร้อมคำแนะนำตามบริบท
  คู่มือเริ่มต้นและการทดสอบการเชื่อมต่อช่วยตั้งค่า ส่วนรูปลักษณ์และภาษาปรับได้ตามการใช้งาน

### คลังสื่อในเครื่อง กู้คืนฉบับร่าง และส่งออกผลงาน

- **ค้นหาสื่อและผลงาน**: ค้นสื่ออ้างอิงที่อัปโหลดและผลลัพธ์ตามประเภทและแหล่งที่มา ดูตัวอย่าง ดาวน์โหลด
  และตรวจสถานะเก็บในเครื่อง เปิด `/media-library` หรือ การตั้งค่า → ประวัติ
- **เก็บความคืบหน้า**: ฉบับร่างเก็บพรอมป์ต์ พารามิเตอร์ และสื่อในเครื่อง ประวัติงานและดัชนีสื่ออ้างอิงก็อยู่บนอุปกรณ์
  การกู้คืนงานรอจะตรวจงานเดิม ไม่ส่งงานสร้างที่เสียเงินใหม่
- **จัดเก็บผลลัพธ์**: ภาพและวิดีโออยู่ใต้ `YYYY/MM/DD` ในโฟลเดอร์ที่เลือกได้สำหรับตัดต่อและส่งมอบ
  การกู้คืนการจัดเก็บจะลองบันทึกผลเดิม ไม่สร้างซ้ำ
- **เตรียมขั้นตอนต่อไป**: ใช้หน้าต่างบันทึกของระบบ ส่งออก PNG/JPEG/WebP และตัดสื่อด้วย FFmpeg WASM ที่โหลดเมื่อจำเป็น

### ขั้นตอนใช้งานสำหรับครีเอเตอร์

1. สำรวจพรอมป์ต์ตัวอย่างหรือจัดข้อความและสื่ออ้างอิงบนแคนวาส
2. เลือกเครื่องมือและโมเดล ตั้งพรอมป์ต์ สื่ออ้างอิง และพารามิเตอร์ที่รองรับ
3. ส่งงาน ดูผลลัพธ์ และปรับการสร้างครั้งต่อไป
4. ค้นผลงานในคลังและนำไฟล์ที่เก็บหรือส่งออกไปใช้ในขั้นตอนถัดไป

การสร้างต้องใช้อินเทอร์เน็ต Flaq AI Client Key ที่ถูกต้อง และเครดิตเพียงพอ โมเดลทำงานบนคลาวด์ ส่วนฉบับร่าง โปรเจกต์
และดัชนีในเครื่องไม่มีการซิงก์คลาวด์ข้ามอุปกรณ์

## เริ่มต้น: เปิดแอปเดสก์ท็อปและเชื่อมต่อ Flaq AI

### สิ่งที่ต้องมี

- Node.js **22** ตาม [.nvmrc](./.nvmrc)
- pnpm **10.5.2** ตาม `packageManager` ใน [package.json](./package.json)
- Rust และ [ข้อกำหนด Tauri](https://v2.tauri.app/start/prerequisites/) ของระบบเป้าหมายสำหรับพัฒนาและสร้างแพ็กเกจ native
  การ build เฉพาะ frontend ไม่ต้องใช้ Rust
- บัญชี Flaq AI และ Client Key สำหรับสร้างจริง การอัปโหลดเริ่มต้น **ไม่ต้องมี** บัญชี Cloudflare ของตนเอง

เรียกจากโฟลเดอร์หลักของโครงการ:

```bash
pnpm install --frozen-lockfile
pnpm desktop:dev
```

รุ่นพัฒนาใช้ `ai.flaq.creator.dev` รุ่นติดตั้งใช้ `ai.flaq.creator` แยกการตั้งค่า ข้อมูล WebView
และโฟลเดอร์สื่อเริ่มต้นจากกัน

### เชื่อมต่อ Flaq AI

1. เข้าสู่ [Flaq AI](https://flaq.ai/th/) และรับ Client Key
2. ทำตามคู่มือเริ่มต้นหรือเปิด การตั้งค่า → การเชื่อมต่อ
3. ใช้ Base URL `https://api.flaq.ai` หรือเกตเวย์ที่เข้ากันได้และเชื่อถือได้
4. ใส่คีย์ ทดสอบการเชื่อมต่อ แล้วบันทึก
5. ใช้ผู้ให้บริการอัปโหลดที่มีมาให้ หรือเลือกตั้งค่า R2 ของตนเองอย่างชัดเจน
6. เลือกเครื่องมือและโมเดล ใส่พรอมป์ต์/สื่ออ้างอิงแล้วส่ง จัดการผลงานที่ การตั้งค่า → ประวัติ และเปลี่ยนโฟลเดอร์ที่
   การตั้งค่า → ทั่วไป

> **การเก็บข้อมูลรับรอง:** “จดจำฉัน” บันทึก JSON ที่อ่านได้ใน `auth.json` ภายในโฟลเดอร์การตั้งค่าของผู้ใช้ปัจจุบัน
> **ไม่ใช่พวงกุญแจของระบบหรือการเข้ารหัสระดับแอป** บน Unix จำกัดสิทธิ์เฉพาะผู้ใช้ปัจจุบัน
> คีย์เฉพาะเซสชันไม่ถูกเขียนลงไฟล์ native นี้ หลีกเลี่ยงการจดจำบนเครื่องที่ใช้ร่วมกัน และอย่า commit คีย์
> บันทึกที่มีความลับ หรือการตั้งค่าในเครื่อง

### อัปโหลดสื่อและเก็บข้อมูลในเครื่อง

| ส่วน                 | การทำงานปัจจุบัน                                                                                                                          |
| -------------------- | ----------------------------------------------------------------------------------------------------------------------------------------- |
| อัปโหลดที่มีมาให้    | Client Key ขอ URL ลงนามอายุสั้นจาก `/api/v1/files/presignedUrl` แล้วอัปโหลดตรง ข้อมูล R2 ส่วนกลางอยู่บนเซิร์ฟเวอร์ ไม่รวมในแพ็กเกจ        |
| R2 กำหนดเอง          | เลือกตั้ง ID บัญชี bucket คีย์เข้าถึง คีย์ลับ และโดเมนสาธารณะ ลงนามในเครื่อง เก็บค่าด้วย AES-GCM ใน WebView ไม่ใช่คลังข้อมูลรับรองของระบบ |
| ฉบับร่าง             | IndexedDB เก็บไบต์และเมทาดาทา การเลือกไฟล์ไม่อัปโหลด อัปโหลดเมื่อส่งงาน                                                                   |
| ประวัติและแค็ตตาล็อก | Web Storage ในเครื่องทำดัชนีงานและสื่ออ้างอิง รายการไม่ได้ให้สิทธิ์เป็นเจ้าของหรือลบไฟล์คลาวด์                                            |
| ไฟล์ผลลัพธ์          | บันทึกแบบสตรีม native ไปยังโฟลเดอร์ที่กำหนด ค่าเริ่มต้นคือข้อมูลแอป การเก็บล้มเหลวไม่ทำให้งานสร้างที่สำเร็จกลายเป็นล้มเหลว                |

R2 ของตนเองต้องมีโดเมนสื่อที่สาธารณะเข้าถึงได้ ไม่ใช่เพียง S3 endpoint ระยะเก็บขึ้นกับนโยบาย Flaq หรือวงจรชีวิต bucket
การเก็บในเครื่องเป็นอิสระจากคลาวด์ การเข้ารหัสค่าในเบราว์เซอร์ไม่ป้องกัน WebView ที่ถูกเจาะ
หรือผู้โจมตีที่เข้าถึงโปรไฟล์และโค้ดแอป ใช้เกตเวย์และปลายทางที่เชื่อถือได้

### โหมด Web เสริม

ยังมีโหมด Next.js เดิมที่รันเซิร์ฟเวอร์:

```bash
pnpm dev
pnpm build
pnpm start
```

เปิด `http://localhost:3000` เมื่อตั้งค่า Web ให้คัดลอก [.env.example](./.env.example) เป็น `.env.local`
ด้วยโปรแกรมแก้ไข และใส่เฉพาะค่าที่จำเป็น

| ตัวแปร                                                                        | การใช้งาน                                    |
| ----------------------------------------------------------------------------- | -------------------------------------------- |
| `NEXT_PUBLIC_SITE_URL`, `NEXT_PUBLIC_CONTACT_US_EMAIL`                        | URL สาธารณะและข้อมูลติดต่อ                   |
| `R2_ACCOUNT_ID`, `R2_ACCESS_KEY_ID`, `R2_SECRET_ACCESS_KEY`, `R2_BUCKET_NAME` | ข้อมูลเฉพาะเซิร์ฟเวอร์สำหรับลงนามอัปโหลด Web |

Web ใช้ `app/api/upload/presigned-url/route.ts` และโดเมนสาธารณะในค่าฝากรูป Desktop ใช้ลายเซ็น Flaq จึงไม่ต้องมีตัวแปร R2
ในเครื่องหรือเซิร์ฟเวอร์ Next.js API ในเครื่อง อย่าเติม `NEXT_PUBLIC_` ให้ความลับหรือใส่ไว้ในตัวติดตั้ง

## สถาปัตยกรรมเดสก์ท็อป: Tauri 2, Rust และ Next.js

**Tauri 2 + Rust แสดง UI Next.js ที่ส่งออกแบบสแตติก โดยไม่มีเซิร์ฟเวอร์ Node.js/Next.js รวมมาด้วย** Desktop และ Web
ใช้หน้า React แบบฟอร์ม ข้อกำหนดโมเดล คำแปล และทรัพยากรออกแบบร่วมกัน

### เทคโนโลยีสมัยใหม่สำหรับงานสร้างสรรค์

- **ส่วน native และ UI สแตติก**: Tauri 2 ใช้ WebView ของระบบ Rust จัดการหน้าต่าง การตั้งค่า และไฟล์ ไม่ต้องมีเซิร์ฟเวอร์
  Node.js ในเครื่อง
- **ชนิดข้อมูลและการตรวจอินพุต**: TypeScript ข้อกำหนดร่วม และ Zod ทำให้แบบฟอร์มตรงกับ API
  ลดพารามิเตอร์ไม่ตรงกันและช่วยเชื่อมโมเดล
- **งานอะซิงโครนัสและโมดูลตามต้องการ**: ตรวจสถานะจากส่วนกลางและจำกัดอัปโหลดพร้อมกัน FFmpeg และการลงนาม R2 โหลดเมื่อใช้
  ลดงานที่ไม่จำเป็นตอนเริ่ม
- **บันทึกอย่างเชื่อถือได้**: Rust ดาวน์โหลดลงไฟล์ชั่วคราวก่อนเผยแพร่ไฟล์สมบูรณ์ ลดผลลัพธ์ไม่ครบเมื่อขาดการเชื่อมต่อ
  แยกสถานะสร้างและจัดเก็บเพื่อกู้คืนได้

### ความเป็นส่วนตัวของไฟล์: เก็บในเครื่องและควบคุมการอัปโหลด

เส้นทางข้อมูลที่ชัดเจนและการตรวจสิทธิ์ช่วยปกป้องสื่อ:

- **ฉบับร่างอยู่ในเครื่องก่อน**: IndexedDB เก็บสื่อและเมทาดาทา เลือกไฟล์อย่างเดียวไม่อัปโหลด เริ่มเมื่อส่งงานสร้าง
- **สิทธิ์อัปโหลดชั่วคราว**: ผู้ให้บริการในตัวขอ URL ลงนามด้วย Client Key ข้อมูล R2 ส่วนกลางอยู่ที่บริการ ไม่อยู่ในแอป
- **ให้สิทธิ์แคนวาสรายไฟล์**: โค้ด native แปลงเป็นเส้นทางจริงและตรวจว่าเป็นสื่อที่จัดเก็บในโฟลเดอร์อนุญาต
  ก่อนให้สิทธิ์ดูไฟล์นั้น
- **แยกการตั้งค่า**: รุ่นพัฒนาและติดตั้งใช้ ID และข้อมูล WebView คนละชุด บน Unix
  มีเพียงผู้ใช้ปัจจุบันที่อ่านและเขียนไฟล์การเชื่อมต่อที่จำไว้ได้

**ขอบเขตความเป็นส่วนตัว:** เก็บในเครื่องไม่ได้หมายถึงทำงานออฟไลน์ทั้งหมดหรือเข้ารหัสไฟล์
พรอมป์ต์และสื่ออ้างอิงที่เกี่ยวข้องถูกส่งไปบริการที่ตั้งค่าไว้ การเก็บบนเซิร์ฟเวอร์ขึ้นกับบริการหรือ bucket Client Key
ที่จดจำเป็น JSON อ่านได้ ไม่ใช่พวงกุญแจระบบ ดู “อัปโหลดสื่อและเก็บข้อมูลในเครื่อง” ด้านบน

### เทคโนโลยีและโครงสร้างโค้ด

| ขอบเขตแพลตฟอร์ม       | HTTP native/Web ส่งออก/บันทึก ลิงก์ภายนอก UI ไม่เรียกคำสั่ง native โดยตรง |

```text

lib/features/       ทะเบียนฟีเจอร์
```

## Build ทดสอบ และสร้างแพ็กเกจเดสก์ท็อป

| คำสั่ง                                            | วัตถุประสงค์                                                  |
| ------------------------------------------------- | ------------------------------------------------------------- |
| `pnpm desktop:dev`                                | เตรียมสื่อ เปิด UI พัฒนาและแอป native                         |
| `pnpm build:desktop`                              | สร้าง frontend สแตติกไป `out/` ครบภาษาที่ลงทะเบียน            |
| `pnpm desktop:build`                              | สร้าง frontend และแพ็กเกจ native สำหรับระบบปัจจุบัน           |
| `pnpm check`                                      | TypeScript + ทดสอบถดถอย Node + ESLint                         |
| `pnpm test:ui-layout`                             | ทดสอบเลย์เอาต์ Playwright ต้องมี Google Chrome และพอร์ต 3000  |
| `cargo test --manifest-path src-tauri/Cargo.toml` | ทดสอบ Rust native ต้องมี dependency สำหรับ build ระบบเป้าหมาย |
| `pnpm prompts:sync`                               | งานดูแล: อัปเดตพรอมป์ต์และทรัพยากรที่คัดเลือกจากเครือข่าย     |

จำลองการสร้างในเครื่องด้วย `pnpm build:desktop` แล้ว `node scripts/desktop-preview.mjs` เปิด `http://127.0.0.1:4173/zh/`
ตั้ง Base URL เป็น `http://127.0.0.1:4173` ใช้ `test-only-key` โดยไม่จดจำ API จำลองไม่ตรวจการสร้าง Flaq จริง อัปโหลด R2
หรือพฤติกรรม native อย่าใช้คีย์จริง

### สถานะแพ็กเกจ

[กระบวนการเผยแพร่](./.github/workflows/desktop-build.yml) กำหนดเป้าหมาย:

| ระบบ                | ไฟล์ผลลัพธ์                                       |
| ------------------- | ------------------------------------------------- |
| macOS Apple Silicon | `.dmg` และ `.app` ใน ZIP                          |
| macOS Intel         | `.dmg` และ `.app` ใน ZIP                          |
| Windows x64         | ตัวติดตั้ง NSIS `.exe` ไม่มี MSI                  |
| Linux               | build จากซอร์ส ยังไม่รวมในเมทริกซ์เผยแพร่ปัจจุบัน |

การรันด้วยตนเองสร้างแพ็กเกจผู้สมัคร แท็ก `desktop-v<version>` ที่ตรงกันเริ่มเผยแพร่ ผลลัพธ์รวม `SHA256SUMS` และ
`release-manifest.json` แพ็กเกจปัจจุบันยังไม่ลงนาม การแจกสาธารณะยังต้องลงนาม/รับรองตามระบบและตรวจเปิดแอป native การมี
workflow ไม่ได้พิสูจน์ว่าทุกระบบ build และทดสอบผ่านแล้ว
