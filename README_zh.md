# Flaq Open Media Creator

面向创作者、设计师与品牌团队的开源
**AI 图片与视频创作桌面客户端**。从提示词灵感、参考素材和无限画布出发，在同一个工作台中完成生成、预览、迭代与本地作品整理，让创作思路更容易变成可交付的内容。

项目改造自 [Flaq SaaS Template](https://github.com/flaqai/flaq-saas-template)，连接 Flaq AI 模型服务，采用 Tauri 2 +
Rust 原生外壳与现代 React 界面。当前安装后的应用名称为 **Flaq Creator**。

## AI 创作客户端功能：从灵感到图片与视频作品

### AI 图片生成、视频生成与虚拟试穿

围绕日常创作提供 8 个入口：可在统一工作台探索想法，也可直接进入专项工具制作电商素材、社交媒体配图、广告概念或短视频。

| 创作功能         | 创作者可以做什么                                         | 页面路径              |
| ---------------- | -------------------------------------------------------- | --------------------- |
| AI Media Creator | 在统一工作区创作图片与视频，查看生成结果并继续调整       | `/ai-media-creator`   |
| AI 无限画布      | 在画布上组织文本、媒体与生成配置，保存并继续本地创作项目 | `/ai-canvas`          |
| 文生图           | 用提示词探索视觉风格，制作封面、海报和产品场景图         | `/text-to-image`      |
| 图生图           | 基于参考图片调整视觉方向，尝试新的风格与表达             | `/image-to-image`     |
| 虚拟试穿         | 结合服装与模特参考图，探索穿搭展示与电商创意             | `/virtual-try-on`     |
| 文生视频         | 将文字创意转化为动态画面，探索故事与广告概念             | `/text-to-video`      |
| 图生视频         | 以静态图片作为输入，制作动态产品展示与视觉片段           | `/image-to-video`     |
| 参考生视频       | 用参考素材引导视频创作，探索连续的视觉表达               | `/reference-to-video` |

页面路径省略语言前缀。入口统一维护在 [功能注册表](./lib/features/catalog.ts)，输入类型、数量限制和参数以所选模型及
[模型能力配置](./lib/constants/template-models/) 为准。

### 提示词灵感库与无限画布：整理思路、探索创意

- **从示例开始创作**：提示词素材库支持复制完整提示词、图片／视频预览，以及缩放和拖动查看，便于学习构图与提示词写法。示例图片随应用提供，示例视频需要联网播放；合集中的模型名称不代表生成表单已经接入该模型。
- **用画布组织项目**：在无限画布上摆放文本、媒体和生成配置，通过平移、缩放与节点操作整理创意，保存本地项目并在之后继续编辑。
- **按创作需求选择模型**：集中调整所选模型支持的参数，结合上下文帮助了解输入要求。首次启动引导和连接测试帮助完成服务配置，外观与语言设置适配日常使用习惯。

### 本地素材管理与草稿恢复：减少重复整理

- **统一查找参考素材和作品**：素材目录聚合已上传参考素材和生成结果，支持按类型、来源筛选和搜索，并提供预览、下载与本地归档状态。可从
  `/media-library` 或“设置 → 历史记录”进入。
- **保留创作进度**：草稿在本机保存提示词、参数和输入素材；任务历史与上传素材索引同样保存在本机。恢复待完成任务时继续查询原任务，不会重新提交一次付费生成。
- **自动归档生成作品**：桌面端将完成的图片与视频按 `YYYY/MM/DD`
  保存到可配置目录，方便后续剪辑、设计与交付。归档恢复只重试保存已有结果，不会重新生成。
- **便捷导出与媒体处理**：支持原生保存对话框、PNG／JPEG／WebP 图片导出，以及按需加载的 FFmpeg
  WASM 裁剪，便于把素材带入后续制作流程。

### 创作者使用流程

1. 在提示词素材库寻找灵感，或在画布中整理文字与参考素材。
2. 选择创作工具和模型，填写提示词、参考素材与可用参数。
3. 提交任务、预览结果，根据作品效果调整下一次创作。
4. 在素材目录中查找作品，将本地归档或导出的文件用于后续制作。

真实生成需要联网、有效的 Flaq AI Client Key 和足够额度。模型在云端运行；本机草稿、项目和素材索引不提供跨设备云同步。

## 快速开始：运行桌面客户端并连接 Flaq AI

### 环境要求

- Node.js **22**，与 [.nvmrc](./.nvmrc) 一致。
- pnpm **10.5.2**，与 [package.json](./package.json) 的 `packageManager` 一致。
- 原生开发与打包需要 Rust 和目标操作系统对应的
  [Tauri 环境依赖](https://v2.tauri.app/start/prerequisites/)。仅构建静态前端不需要 Rust。
- 真实生成需要 Flaq AI 账号和 Client Key；默认桌面图床**不要求自行申请 Cloudflare 账号**。

在本仓库根目录执行：

```bash
pnpm install --frozen-lockfile
pnpm desktop:dev
```

开发版使用独立应用标识 `ai.flaq.creator.dev`，安装版使用
`ai.flaq.creator`。两者的配置、WebView 数据和默认作品目录互相隔离。

### 连接 Flaq AI

1. 登录 [Flaq AI](https://flaq.ai/zh/)，获取 Client Key。
2. 按首次启动引导操作，或打开“设置 → 连接”。
3. Base URL 默认使用 `https://api.flaq.ai`；也可以填写兼容且可信的网关。
4. 填写 Client Key，测试连接并保存。
5. 保留内置图床，或主动配置自己的 R2 预设。
6. 选择工具与模型，填写提示词／参考素材后提交；在“设置 → 历史记录”管理结果，在“设置 → 通用”修改作品存储目录。

> **密钥保存方式：**勾选“记住我”后，连接信息以可读 JSON 保存到当前用户应用配置目录下的
> `auth.json`。它**不是系统钥匙串，也没有应用层加密**。Unix 下限制为当前用户访问；不勾选时，会话密钥不会写入该原生文件。共享设备不建议记住密钥；不要提交密钥、含敏感信息的日志或本地配置。

### 素材上传流程与本地数据存储

| 数据／流程     | 当前实现                                                                                                                     |
| -------------- | ---------------------------------------------------------------------------------------------------------------------------- |
| 桌面内置图床   | 使用 Client Key 向 Flaq 的 `/api/v1/files/presignedUrl` 请求短时签名链接，再直传素材；共享 R2 凭据保留在服务端，不打进安装包 |
| 桌面自定义 R2  | 可选配置账号 ID、桶、Access Key、Secret Key 与素材公网域名；本机签名，预设使用 WebView 中的 AES-GCM 存储，不是系统凭据保险库 |
| 输入草稿       | IndexedDB 保存素材字节和元数据；选中文件不会立即上传，提交生成时才上传                                                       |
| 历史与素材目录 | Web Storage 保存本机任务记录和已上传素材索引；目录记录不代表素材所有权或云端删除权限                                         |
| 生成文件       | 原生流式保存到配置目录，默认位于应用数据目录；归档失败不会把已完成生成改成失败                                               |

自定义 R2 需要可公开访问素材的域名，而不是直接使用 S3
API 端点。云端保留时间由 Flaq 服务策略或自己的桶生命周期决定，与本地归档相互独立。自定义预设的浏览器侧加密不能防御被攻陷的 WebView，或能够读取应用数据及代码的攻击者；仅使用可信的 API 网关和上传目标。

### 可选的 Web 模式

项目保留运行 Next.js 服务端的 Web 模式：

```bash
pnpm dev
# Web 生产模式
pnpm build
pnpm start
```

浏览器访问 `http://localhost:3000`。如需配置 Web 环境，使用编辑器将 [.env.example](./.env.example) 复制为
`.env.local`，按需填写：

| 环境变量                                                                      | 用途                             |
| ----------------------------------------------------------------------------- | -------------------------------- |
| `NEXT_PUBLIC_SITE_URL`、`NEXT_PUBLIC_CONTACT_US_EMAIL`                        | 公开的站点地址与联系邮箱         |
| `R2_ACCOUNT_ID`、`R2_ACCESS_KEY_ID`、`R2_SECRET_ACCESS_KEY`、`R2_BUCKET_NAME` | Web 上传签名接口使用的服务端凭据 |

Web 上传使用
`app/api/upload/presigned-url/route.ts`，并读取“图床”设置中的公网域名。桌面默认走 Flaq 签名服务，不需要本地 R2 环境变量，也没有本地 Next.js
API 服务。不要给任何密钥添加 `NEXT_PUBLIC_` 前缀，也不要将密钥放进安装包。

## 桌面客户端技术架构：Tauri 2、Rust 与 Next.js

**Tauri 2 + Rust 承载 Next.js 静态导出的界面，安装包不内置 Node.js／Next.js 服务端。**
桌面端与 Web 端共享 React 页面、表单、模型契约、翻译与设计资源。

### 现代技术如何支持创作体验

- **原生外壳与静态界面**：Tauri
  2 使用系统 WebView 承载界面，Rust 处理系统窗口、配置和文件保存；桌面安装包无需运行本地 Node.js 服务。
- **类型与输入校验**：TypeScript、共享模型契约和 Zod 校验统一表单与请求的数据约定，帮助减少参数不匹配，让新增模型能力更易维护。
- **异步任务与按需加载**：集中管理任务轮询、限制上传并发，FFmpeg 和自定义 R2 签名模块按需加载，减少不必要的启动工作。
- **可靠保存作品**：Rust 流式下载先写入临时文件，完成后再发布为目标文件，减少下载中断留下不完整成品的风险；生成和归档分别记录状态，方便恢复。

### 文件隐私与安全：本地存储、按需上传和访问边界

客户端通过明确的数据流和文件访问检查保护创作资料：

- **草稿先留在本机**：输入素材字节和元数据保存在 IndexedDB；选中文件不会立即上传，提交生成时才进入上传流程。
- **上传凭据按需获取**：默认图床通过 Client Key 获取短时签名上传链接，共享 R2 密钥保留在服务端，不随安装包分发。
- **画布本地文件按文件授权**：原生层解析真实路径，检查文件是否为允许的作品目录中的归档媒体，再为该文件开放预览访问。
- **本机配置分开管理**：开发版和安装版使用独立应用标识，隔离配置与 WebView 数据；Unix 下记住的连接配置文件限制为当前用户读写。

**隐私边界：**本地保存不等于全程离线或文件加密。提交生成后，相关提示词和参考素材会发送到配置的服务，云端素材保留时间取决于服务或存储桶策略。记住的 Client
Key 当前以可读 JSON 保存，并未接入系统钥匙串；详细存储方式见上方“素材上传流程与本地数据存储”。

### 技术栈与代码目录

| 层次           | 技术与职责                                                                |

桌面构建在独立临时副本中排除 Web 专用路由，成功后才替换
`out/`，不会搬移或删除源码路由。桌面 HTTP 请求、上传和下载使用原生适配层，不依赖浏览器 CORS。自定义 R2 的 AWS 签名模块、裁剪所需的本地 FFmpeg 资源按需加载；上传限制并发，共享媒体处理串行执行，任务轮询集中管理。

扩展功能时，先补功能注册表和模型契约；API 逻辑放入 `network/`，复用
`lib/platform/`，同步翻译与回归测试，避免在页面里重复实现上传、轮询或原生命令。详细文档：

- 桌面路由始终包含语言前缀，包括 `/en/`；启动时优先使用已保存语言，其次系统语言，最后英语。繁体中文系统变体映射到 `tw`。
- Web 英语使用 `/`，其他语言使用前缀；阿拉伯语设置 RTL 文档方向。
- **当前限制：**部分新增设置、素材目录与提示词素材库文案直接使用中英文。 `zh`／`tw`
  共用中文文案，其他语言在这些面板中回退到英文；注册了 15 个语种不代表每条新界面文案都已翻译完成。
- 新增语种需同步 [i18n/languages.ts](./i18n/languages.ts)、`messages/`、路由与构建的语种处理、对应 README 和一致性测试。
